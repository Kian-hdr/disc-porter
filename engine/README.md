# Disc Porter engine 0.2

The authenticated loopback server is `engine.server.serve(state_dir)`. Development requires Python 3.10+; tests use Python 3.12. The packaged application uses its frozen helper and bundled tools, without requiring the user to install Python. `engine/helper.py` belongs to packaging and dispatches `serve`, `supervise` and `mcp`. Supervision invokes helper dispatch when frozen. Every media-reading tool, including scans, probes and stream hashes, inherits the single-owner state lock and is reaped before the lock is released after interruption.

Modules:

- `core.py`: retained v1 pipeline foundation, structural identity, bounded robot parsing, measured tool progress and durable SQLite records.
- `schema.py`: v2 defaults, field capabilities, immutable builtin recipes, validation and supported limits.
- `service.py`: v2 control plane, revision checks, planning snapshots, per-title checkpoints, ownership and cleanup journal, processing integration, audit and metadata.
- `media.py`: explicit SDR video transforms and source-index audio/subtitle mapping.
- `mp4.py`: bounded MP4 text-track `tkhd` enabled-flag correction, followed by probe/decode/hash verification.
- `transfers.py`: durable per-file verified exports, no-overwrite publication and stale-worker epochs.

The shared interface is `docs/API_V2.md`; legacy routes remain available. Bearer token, exact loopback Host and browser Origin rejection protect the API. State is private, and tokens, credentials and real media details never belong in Git. Settings/presets/profiles/jobs have optimistic revisions. New job creation supports idempotency. Preview supplies a `plan_fingerprint`; start validates it before source hashing and validates a coherent settings/preset/profile/source snapshot again at commit. Heavy hashing and media inspection run outside the database mutex, while reader activity prevents false safe-disconnect reporting.

Schema migration backs up the existing SQLite database with SQLite's backup API. Saved v1 values map to Legacy with Keep retention; existing job paths/names and recipe snapshots remain. Legacy originals are never cleanup eligible. Preset → global default recipe overrides → disc profile → job → title determines new recipes. Active jobs retain their recipes and tool paths. Builtins are immutable; custom presets require revisions. Unsupported combinations return an actionable correction. Parallel encoder count is explicitly limited to one; software CPU threads are configurable. Hardware availability is established with compiled-encoder inspection and small synthetic SDR 8-bit pilots, with source-class limits disclosed. Actual output is independently validated; no hidden software fallback is enabled.

A read-only scan never starts acquisition. Mount polling can auto-start exact saved profiles only when enabled. Structural IDs identify control-file structure, not a physical pressing serial. Disc labels, playlist order and duration do not establish official identity. Profiles and jobs require explicit title mappings. Series starts through the v2 composer require confirmed season/episode. Organized output uses `Movies/`, `TV/`, or `Extras/`, then collection and applicable season. Flat retains a collection folder. Naming tokens require supplied metadata; no year or episode is invented.

Every completed title phase is a durable checkpoint. Aggregate phase fields advance only after all titles commit that phase. Next checkpoint stops after one durable title; whole-disc checkpoint requests remain supported. A stopped phase restarts in a new attempt, preserving older candidates and generations. Resume after acquisition can use originals without the disc. Stop Now terminates only owned tools and waits for them; manual pauses survive global resume. Prepare to Disconnect fences new jobs/scans atomically, pauses workers at durable title boundaries and stops scanners. Safe state includes readers, subprocesses, workers, scans, transfers and cleanup. Finder eject remains separate.

Missing or changed source/destination identities become explicit waiting states. Power policy checks macOS battery state. All bound roots have space/reserve checks, with known source/acquisition sizes where available. Automatic resume affects condition waits, not manual pauses. Retry limits apply to transient processing failures and retain prior attempts. Separate real media progress, output-byte throughput, ETA estimates, committed-item counts, advancement timestamps and engine heartbeats are reported. Overall progress counts committed title checkpoints, not invented duration/byte weighting.

Acquisition requests every stream through direct-copy MakeMKV settings and compares resulting inventory with scan evidence. Imported files are stream-copy remuxed into new app-created MKVs; imported sources remain untouched. Complete originals are exposed after full decode. Work, original and output roots can differ. Publication uses atomic no-clobber hardlinks, with verified copy fallback across volumes. Existing different files are never replaced.

Transcode supports SDR 4:2:0 8/10-bit sources, explicit resize/frame-rate/deinterlace/aspect transformations and source bit depth. Auto deinterlacing uses frame interlace flags when source headers identify interlace. HDR/Dolby Vision transcode requires Original mode instead. A preset alone cannot silently approve 10→8 conversion: preview requires explicit confirmation, or an explicit bit-depth override; optical sources discovered later pause for that approval. Original mode performs no lossy encoding, retains its final original archive deliverables, and disallows deleting them.

Empty language lists mean every source language. Main-per-language selection honors source defaults or declared language order; independent unknown-tagged tracks remain independent. Manual indices, default audio/subtitle indices and forced-subtitle lists are validated against the acquired media. Unknown tags remain `und`. AAC/AC-3 and explicit stereo transforms record actual mapping; copied audio requires packet-payload equality. MP4-incompatible copied codecs require MKV or transcoding. Source audio and subtitle sidecars retain original packet payloads and metadata. Text export verifies normalized cue content/timing and default/forced flags; original subtitle styling remains available in source/sidecar. Bitmap subtitles remain in verified sidecars. Text burn requires an available libass filter; incompatible compositions reject before processing.

Technical verification checks planned geometry, rate, depth, color, duration, selected stream counts, channels/languages/default/forced flags, full audio/video decode, copied packet payloads and text cue projections. Final candidates are hashed before publication. File and ancestor directory sync precede committed archive mutations. Library distinguishes known changed/missing deliverables; exports require recorded verified hashes, not newly invented verification evidence. Manual playback/perceptual acceptance stays pending until explicitly recorded and is never fabricated.

Retention defaults to Keep. `delete_verified` is optional and requires enabled original-audio and bitmap-subtitle preservation. It deletes only newly app-created, technically verified temporary originals covered by an exact ownership ledger and prepared journal. Every alias, inode, hash and unexpected hardlink is checked. Imported sources, legacy originals, original-archive deliverables, unrelated paths and originals referenced by another job or its retained generations are protected. Cleanup claims and reprocessing claims are serialized. Recovery replays prepared deletion journals idempotently. Only journal-covered ledger entries change to deleted; retained older generations remain accurately recorded. Required stream sidecars/finals must verify first. This explicit policy does not require manual playback acceptance.

Metadata lookup is optional. Local suggestions remain confirmation-only. TMDb is disabled until opted in; only the user-provided text query goes to its API. Credential storage uses macOS Keychain service `dev.discporter.tmdb`, account `api-token`, with no token in settings/reports/audit. Keychain mutation tests use mocks. Appearance and notification preferences are surfaced for the native UI, with completion/failure audit events provided; the engine never runs an arbitrary shell.

Run the synthetic test suite:

```bash
/opt/homebrew/bin/python3.12 -m unittest discover -s tests/engine -v
```

Tests generate disposable media and fake MakeMKV responses. They cover v1 compatibility, migration, revision/idempotency/preview conflicts, real H.264/Main10 HEVC, SDR filters, surround/downmix, copied audio, subtitles/flags/cues/sidecars, cleanup protection/recovery, exports/copy fallback, per-title checkpoints, stop/disconnect, reader crash/timeout supervision and measured progress. Physical discs, general-player/TV acceptance, physical sudden-power-loss recovery and all hardware source classes remain untested.

Workflow design was informed by the installed `dvd-digitize-archive` skill and its processing/Blu-ray references. Implementation is original; no private configuration or copied third-party source is included.
